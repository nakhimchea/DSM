# 02 · What data to collect

The catalogue lives in `configs/data/sources.yaml`. Every source has a kind, languages, a licence,
a **tier**, and the producer of the text (`generated_by`). `dsm data sources` shows the licence
decision for each one:

```
OK  fineweb2_km    pretrain   km      use: ODC-BY-1.0
NO  wikipedia_km   pretrain   km      needs counsel sign-off (CC-BY-SA-4.0); pass --accept-counsel once approved
NO  pku_saferlhf   preference en,zh   blocked: noncommercial (CC-BY-NC-4.0)
```

Repository ids marked `verify` must be checked on the hub before the first download. Ids and
configs change, and the catalogue cannot be tested offline.

## 1. By training stage

| Stage | Data type | Sources (catalogue names) | Target volume (24 GB plan) |
|---|---|---|---|
| CPT: Khmer | web + curated text | `fineweb2_km`, `hplt3_km`, `hplt2_km` (use); `wikipedia_km`, `voa_khmer` (counsel) | all good Khmer you can get: ~1–3B raw tokens, ~1B after cleaning |
| CPT: replay | English / Chinese text | `fineweb_edu`, `dclm`, `fineweb2_zh`, `hplt3_zh`, `industrycorpus2_finance` | 40 % of CPT tokens (sampled, < 1 epoch) |
| CPT: skills | math, code, tables | `finemath`, `open_web_math`, `stack_edu_python` (counsel) | 7 % of CPT tokens |
| CPT: bridges | parallel km–en / km–zh | `alt_km_en`, `massive_km`, `tico19`, `nllb_mined_km_en` (counsel, filter hard) | 7 % of CPT tokens |
| Anneal | best documents, instruction-formatted text, identity documents | top-scored subsets of the above; `dsm data render-sft`; `dsm build identity` | 0.3–0.5B tokens |
| SFT | conversations | `smoltalk2`, `nemotron_post_training_v1`, `xlam`, `toolace`, `hermes_fc`, `glaive_fc_v2`, `when2call`, `tabfact`, `tatqa`, `finqa`, `gsm8k`, `hendrycks_math`, plus DSM's own builders | ~200K conversations |
| DPO | preference pairs | `helpsteer3`, plus on-policy pairs and DSM builders | 20–40K pairs |
| Safety | prompts (responses are generated locally) | `aegis2`, `wildguardmix`, `xstest`, `do_not_answer`, `safety_prompts_zh` | ~8 % of SFT |
| Evaluation only | benchmarks | `belebele*`, `flores_plus*`, `sib200*` (one entry per language) | never trained on (`eval_only`) |

## 2. Khmer: the scarce resource

* **Volume.** Expect 1.5–3B unique raw Khmer tokens across the large crawls, and about 1B after
  cleaning and deduplication. FineWeb-2 and HPLT overlap heavily, so deduplicate across them,
  feeding the better source first.
* **Typical defects** (handled by `dsm data clean`):
  * non-canonical cluster order (`ខែ្មរ` → `ខ្មែរ`);
  * zero-width spaces used as word separators;
  * deprecated inherent vowels;
  * legacy-font text (Limon / ABC) that looks like Latin-1 symbols;
  * pages that are mostly English menus around a little Khmer.
* **Repetition budget.** At most about 4 epochs over the Khmer pool in CPT. `dsm data mix` caps it
  and redistributes the remainder.
* **Parallel and translated data.** Parallel text teaches the mapping between languages, and
  translation (local Apache/MIT teacher, protected spans) multiplies SFT data. Never use NLLB-200
  model outputs: the model is non-commercial.
* **Human review.** Khmer seed data, translated SFT samples and evaluation items should be checked
  by native speakers before production. The repository flags every such file.

## 3. Licence tiers (details in [12_licensing_provenance.md](12_licensing_provenance.md))

| Tier | Rule | Examples |
|---|---|---|
| `use` | commercial training allowed; keep attribution in the data card | CC0, ODC-BY, CC-BY, Apache-2.0, MIT sources |
| `needs_counsel` | download only with `--accept-counsel` after sign-off | CC-BY-SA (Wikipedia, WTQ), dataset-specific agreements, proprietary-model rewrites (NuminaMath solutions), code with per-file licences |
| `eval_only` | never mixed into training | Belebele, FLORES+, SIB-200 |
| `blocked` | refused: non-commercial, naming / derivative clauses, suspended | NLLB-200 outputs, Bactrian-X, Alpaca derivatives, BELLE, MAP-CC, APIGen-MT, PKU-SafeRLHF, BeaverTails, FalseReject, OpenMathInstruct-2, Tulu-3 preference mix, OSCAR |

Text generated by a model whose licence propagates (Llama naming clause, Gemma "model
derivative") is refused even when the dataset's own licence is permissive. The gate checks
`generated_by`.

## 4. Your own (internal) data

The most valuable data for a bank assistant is your own: product sheets, fee schedules, FAQs,
policies, branch information, anonymised support conversations. Treat it as follows:

* clean it with `dsm data clean --name <name> --license internal --internal`. This applies strict
  PII redaction: account-like ids and any run of 6+ digits become placeholders, on top of e-mails,
  phones, cards, IBANs and IPs;
* put facts into **RAG documents** (`dsm build rag --documents ...`) rather than relying only on
  memorisation. Facts change, and grounded answers can cite their source;
* data cards of internal datasets are marked **INTERNAL**. A model trained on them must not be
  published.

## 5. Adding a source

```yaml
- {name: my_khmer_news, kind: pretrain, langs: [km], tier: use, license: CC-BY-4.0, generated_by: human,
   hf: {repo: org/dataset, config: km, split: train, text_field: text}, verify: true,
   notes: "where it comes from, known issues"}
```

SFT sources also name a `converter` (see `dsm.data.builders.datasets.DATASETS`), and may list
`exclude_subsets` (glob patterns on the row's `source` / `subset` field). Run `dsm data sources`
afterwards: it validates every entry and fails on inconsistent tiers, such as an NC licence marked
`use`.
